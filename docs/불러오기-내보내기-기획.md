# 불러오기 · 내보내기 기획

족보를 파일로 꺼내고(내보내기), 파일에서 들여오는(불러오기) 기능의 기획입니다. 2026.11.1~11.5에서 요청마다 덧붙여 만든 것을 처음부터 다시 정리했습니다. 개발과 시험은 이 문서를 기준으로 합니다.

## 1. 쓰는 사람의 상황

| # | 상황 | 쓰는 형식 | 흐름 |
| --- | --- | --- | --- |
| A | 다른 족보 프로그램(MyHeritage, Gramps 등)에 있던 족보를 옮겨 온다 | GEDCOM | 그 프로그램에서 .ged 내보내기 → 우리 앱 [불러오기] → **새 족보** |
| B | 엑셀로 족보를 처음 정리해 들여온다 | 엑셀 | [불러오기] → 엑셀 양식 받기 → 채우기 → [불러오기] → **새 족보** |
| C | 우리 족보를 엑셀에서 고쳐 되돌린다 | 엑셀 | [내보내기] 엑셀 → 엑셀에서 고침 → [불러오기] → **기존 족보에 반영** |
| D | 우리 족보를 다른 프로그램이나 친척에게 넘긴다 | GEDCOM | [내보내기] GEDCOM → 파일 전달 |
| E | 반영을 잘못해서 되돌린다 | GEDCOM 백업 | [불러오기] → 백업에서 불러오기 → 새 족보로 만들어 확인 |

## 2. 원칙

1. **불러오기는 먼저 보여 주고, 확인을 받은 뒤 저장합니다.** 저장은 전부 되거나 하나도 되지 않습니다.
2. **사람은 지우지 않습니다.** 파일에서 사람을 지워도 족보에서는 지우지 않고, 미리보기에 "파일에 없는 사람"으로 알립니다. 지우는 것은 앱에서 직접 합니다.
3. **같은 사람은 번호로 알아봅니다.** 이름은 바뀌거나 겹칠 수 있으므로, 내보낸 파일의 모든 사람에게 그 족보 안의 번호를 붙입니다. 엑셀의 행 번호는 행을 끼우면 바뀌므로 어디에도 쓰지 않습니다.
4. **반영하기 전에 백업합니다.** 백업은 GEDCOM 파일이고, 불러오기 창에서 바로 다시 불러올 수 있어야 합니다.
5. **트리로 못 그리는 관계도 빠뜨리지 않습니다.** 엑셀 트리에 담기지 않는 관계는 따로 적습니다.

## 3. 화면

### 내보내기 창

```
내보내기                                                   [×]
내보낼 족보  [ 청도김씨대동보 · 152명            ▼ ]   ← 처음에는 지금 보고 있는 족보
┌─ 엑셀 가계도 (.xlsx) ──────┐ ┌─ GEDCOM (.ged) ─────────────┐
│ 트리 모양 그대로. 고쳐서    │ │ 국제 표준 족보 파일. 다른    │
│ 다시 불러올 수 있습니다.    │ │ 족보 프로그램으로 옮깁니다.  │
└────────────────────────────┘ └─────────────────────────────┘
파일은 내려받기 폴더에 저장됩니다.
```

- 족보 이름이 같은 경우가 있으므로 인원을 함께 보여 줍니다.

### 불러오기 창

```
족보 불러오기                                              [×]
GEDCOM·엑셀·CSV를 새 족보로 불러옵니다. 이 앱에서 내보낸 뒤 고친
파일이면 원래 족보에 반영할 수도 있습니다.
파일 [파일 선택 ……………………………………………]            최대 20MB
양식 받기: 엑셀 양식(.xlsx) · GEDCOM 양식(.ged)   백업에서 불러오기 ▸
- - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
불러오는 곳 (•) 기존 족보 「청도김씨대동보」에 반영  ( ) 새 족보로 만들기
반영 내용 · 새로 추가 1명 · 고침 2명 · 그대로 149명 · 관계 추가 1건
  추가: 김새손
  · 김지영 — 사망일 (없음) → 2015-10-13
  · 족보 정보 — 파명 現風琴山 → 玄風琴山
  파일에 없는 사람 1명(김도윤)은 지우지 않고 그대로 둡니다.
  반영하기 전에 지금 족보를 백업 파일로 저장해 둡니다.
──────────────────────────────────────────────────────────
                                   [닫기]  [기존 족보에 반영]
```

- "새 족보로 만들기"를 고르면 족보명 칸과 가계도 미리보기가 보입니다.
- "백업에서 불러오기 ▸"를 누르면 백업 목록(족보명, 날짜·시각)이 펼쳐지고, 고르면 그 파일을 미리보기로 읽습니다.

## 4. 엑셀 파일 규칙

### 시트

| 시트 | 내용 | 불러올 때 |
| --- | --- | --- |
| 가계도 | 트리. 한 행에 한 사람 | 읽음 |
| 추가 관계 | 트리로 못 그린 관계 | 읽음 |
| 족보 정보 | 족보명·성씨·본관…, 족보 번호 | 읽음 |
| 인물 목록 | 정렬·필터용 목록 | 읽지 않음 |
| 작성 안내 | 이 규칙의 요약 | 읽지 않음 |

### 가계도 시트

| 열 | 뜻 |
| --- | --- |
| `25세`, `26세` … | 이름을 적는 열. 이름이 있는 열이 세대. 오른쪽으로 한 칸 = 바로 위 사람의 자녀 |
| 세 | 실제 세(世). 비우면 머리글 따름 |
| 성별, 본관, 출생일, 사망일, 기록 | 그 사람의 기록 |
| 다른 부모 | 배우자가 둘 이상일 때 이 자녀의 다른 부모 이름. 모르면 `(미상)` |
| 번호 | 족보 안의 사람 번호. **고치지 않습니다.** 새로 끼운 행은 비워 둡니다 |

- 배우자: 그 사람 바로 아래 행, 같은 열에 `配 이름`.
- 이미 다른 행에 적힌 사람: `→ 번호 12` (예: `配 李氏(이씨) → 번호 12`). 번호는 행을 끼워도 바뀌지 않습니다. 예전 파일의 `→ 12행`도 읽습니다.

### 추가 관계 시트

| 관계 | 번호 | 이름 | 번호 | 이름 |
| --- | --- | --- | --- | --- |
| 부모-자녀 | 12 | 李氏 | 40 | 朴某 |
| 배우자 | 7 | … | 15 | … |

- 부모-자녀는 앞이 부모, 뒤가 자녀입니다. 이름 칸은 읽기용이고 불러올 때는 번호만 봅니다.
- 내보낼 때, 가계도 시트를 다시 읽어 얻은 관계와 족보의 관계를 비교해 빠진 것만 여기에 적습니다.

### 인물 목록 시트

- 첫 열을 `행` 대신 **`번호`**로 바꿉니다. 가계도 시트의 번호와 같은 값이라 두 시트에서 같은 사람을 찾을 수 있습니다.

## 5. GEDCOM 규칙

- 5.5.1, UTF-8로 내보냅니다. 한글명이 첫 이름, 한자명은 `TYPE aka` 이름.
- 사람 번호는 표준 `REFN`(`TYPE jocbo`), 세·본관은 `_GEN`·`_BONGWAN`.
- 족보 정보와 족보 번호는 파일 머리의 메모(`HEAD NOTE`)에 "족보명: …" 같은 줄로 적습니다. 처음에는 `_BOOK` 태그였으나 Gramps가 "이해하지 못한 줄"로 보고해서 바꿨습니다. 예전 `_BOOK` 파일도 읽습니다.
- Gramps 6.0.8 시험: 가져오기 보고 "No errors detected". Gramps를 거친 파일은 머리 메모가 빠지므로 새 족보로만 불러옵니다(세·본관·사람·관계는 그대로).
- 불러오기는 5.5·5.5.1·7.0, UTF-8·UTF-16·CP949. Gramps가 바꿔 쓰는 `EVEN`+`TYPE _GEN` 모양도 읽습니다.
- 정확하지 않은 날짜(ABT, BET …)와 출생지·묘소·직업은 기록(메모)으로 옮깁니다.

## 6. 기존 족보에 반영

- **대상:** 파일의 족보 번호가 이 계정의 족보와 같을 때만 "기존 족보에 반영"을 보여 줍니다. 다른 프로그램의 파일은 새 족보로만 불러옵니다.
- **사람:** 번호가 맞는 사람은 파일 내용으로 고칩니다. 번호가 없거나 족보에 없는 번호는 새 사람으로 더합니다. 같은 번호가 두 번 나오면 두 번째는 새 사람입니다.
- **관계:** 파일에 있는 사람끼리의 부모·배우자 관계는 파일대로 맞춥니다(가계도+추가 관계). 파일에 없는 사람이 걸린 관계는 그대로 둡니다.
- **족보 정보:** 족보 정보 시트(또는 GEDCOM `_BOOK`)가 바뀌었으면 함께 고칩니다. 미리보기에 보여 줍니다.
- **지우지 않음:** 파일에 없는 사람은 미리보기에 이름을 보여 주고 그대로 둡니다.
- **백업:** 반영 직전에 `%LocalAppData%\jocbo\backups\족보명_날짜-시각.ged`로 저장합니다.
- **무료판:** 새로 더하는 인원만큼 20명 제한을 적용합니다.
- **검사:** 반영 뒤 족보 전체에 부모-자녀 순환이 생기면 반영하지 않습니다.

## 7. 경계 상황

| 상황 | 처리 |
| --- | --- |
| 엑셀에서 행을 끼움 | 번호가 비어 있으니 새 사람. 참조는 번호 기준이라 깨지지 않음 |
| 엑셀에서 행을 지움 | 그 사람은 "파일에 없는 사람"으로 알리고 남겨 둠 |
| 자녀 행을 다른 부모 아래로 옮김 | 그 자녀의 부모 관계가 옮겨짐 |
| 번호 칸을 잘못 고침 | 족보에 없는 번호면 새 사람, 다른 사람의 번호면 그 사람이 고쳐짐(미리보기에 이름 변경으로 드러남) |
| 같은 이름 | 번호로 구분하므로 문제없음 |
| 재혼(배우자 둘) | 配 행 두 개, 자녀는 "다른 부모"로 구분 |
| 배우자의 전혼 자녀, 양쪽 집안 모두 기록된 혼인 | 트리로 못 그리면 추가 관계 시트 |
| 족보 번호 칸을 지움 | 새 족보로만 불러옴 |
| 다른 PC에서 내보낸 파일 | 족보 번호가 없으니 새 족보로만 불러옴 |

## 8. 시험 항목

자동 시험(`tests/test_exchange.py`)과 화면 클릭 시험, 실제 엑셀 편집 시험을 모두 돌립니다.

1. 예제 족보 → 엑셀·GEDCOM 내보내기 → 새 족보로 불러오기: 사람·관계·세·기록·족보 정보가 같음
2. 트리로 못 그리는 관계(배우자의 전혼 자녀)가 있는 족보: 엑셀 왕복 후 관계가 같음(추가 관계 시트)
3. 엑셀에서 행 끼우기(새 손주) → 반영: 1명 추가, 부모 연결, `→ 번호` 참조 깨지지 않음
4. 엑셀에서 사망일 고치기 → 반영: 고침 1명, 미리보기에 바뀐 칸 표시
5. 엑셀에서 행 지우기 → 반영: 그 사람이 남아 있고 "파일에 없는 사람"으로 표시
6. 엑셀에서 자녀 행을 다른 형제 아래로 옮기기 → 반영: 부모 관계가 옮겨짐
7. 족보 정보 시트의 파명 고치기 → 반영: 족보 정보가 바뀜
8. 반영 뒤 백업 파일이 생기고, "백업에서 불러오기"로 새 족보로 되살릴 수 있음
9. 다른 족보의 파일은 그 족보에 반영할 수 없음
10. 무료판: 반영으로 20명을 넘으면 안내 창, 아무것도 저장되지 않음
11. 내보내기 창에서 다른 족보를 골라 내려받으면 그 족보가 나옴
12. Gramps를 거친 GEDCOM: 새 족보로 불러와 세·본관이 그대로
13. 잘못 그린 트리: 고칠 행 번호를 알리고 저장 막음
14. 설치판(바탕화면 아이콘)에서 내보내기·불러오기·반영을 직접 눌러 확인
