# 우리의 족보 — FastAPI 족보·가계도 MVP

한국어 화면에서 회원가입, 로그인, 족보 생성, 인물 관리, 가족 관계, 검색, 가계도, 족보책 미리보기와 인쇄/PDF 저장을 사용할 수 있습니다. 족보 사진을 올려 판독한 결과로 인물 여러 명을 한 번에 등록할 수도 있습니다.

가계도는 기록된 세대를 그대로 줄로 쓰고 부부를 한 묶음으로 배치하며, 카드의 `+` 로 부모·자녀·배우자·형제자매를 그 자리에서 추가합니다. 재혼이면 배우자별로 자녀 선이 갈립니다. 혼인으로 들어온 사람의 친가 윗대는 점선과 `外家` 로 구분하고 족보책에서는 제외합니다. 족보책 미리보기는 한 면에 여섯 세대 칸을 두고 세로쓰기 한자로 전통 서책 형식을 재현합니다.

`db/seed.sql` 과 `db/seed.py` 의 예제는 가상 인물입니다. `db/seed_reference_page.py` 는 실제 족보 사진에서 옮긴 기록이므로 **실존 인물의 이름과 생년월일이 들어 있습니다.** 공개 저장소에서 쓸 때는 이 점을 알고 쓰세요.

## 한 번에 설치하고 실행 (Windows)

`install.bat` 한 파일만 내려받아 두 번 누르면 프로그램을 받고, 파이썬과 꾸러미를 설치하고, 브라우저까지 엽니다. GitHub 계정이나 로그인은 필요 없습니다. 저장소가 공개라서 받기만 하는 데는 인증이 없습니다.

- 받을 곳: `%USERPROFILE%\Documents\jocbo`
- git이 있으면 `git clone`, 없으면 압축파일로 받습니다.
- 파이썬이 없으면 winget으로 설치할지 묻습니다. winget이 없으면 <https://www.python.org/downloads/> 를 안내합니다.
- 바탕화면에 **우리의 족보** 바로가기를 만듭니다. 다음부터는 이것만 누르면 됩니다.
- 크롬이 설치돼 있으면 크롬으로, 없으면 기본 브라우저로 <http://127.0.0.1:8000> 을 엽니다.
- 판독기는 약 200MB라 설치 여부를 한 번 묻습니다. 20초 안에 답하지 않으면 건너뜁니다. 나중에 `start.bat`을 다시 실행하면 또 묻습니다.

이미 받아 둔 폴더에서는 `start.bat`을 두 번 누릅니다. 설치는 처음 한 번만 하고, 다음부터는 바로 열립니다. 열 때마다 GitHub에 새 판이 있는지 확인해, 있으면 `install.bat`으로 넘겨 백업과 갱신을 마친 뒤 엽니다. 인터넷이나 git이 없으면 지금 판으로 열고, 이 폴더에만 있는 커밋이 있으면(고치는 컴퓨터) 건드리지 않습니다.

| 파일 | 하는 일 |
| --- | --- |
| `install.bat` | 내려받기 · 설치 · 실행. 이미 받아 둔 폴더면 서버를 멈추고 GitHub 최신과 똑같이 맞춘 뒤 실행 |
| `start.bat` | 새 판 확인(있으면 갱신) · 설치 확인 후 실행 |
| `stop.bat` | 돌고 있는 서버 중지 |

**최신으로 갱신할 때는 `install.bat`을 다시 누릅니다.** 서버를 멈추고, 폴더를 GitHub 최신과 똑같이 맞추고, 늘어난 꾸러미를 설치한 뒤 다시 띄웁니다.

- **족보 DB(`jocbo.db`)와 그 컴퓨터에서 올린 사진은 갱신하지 않습니다.** 컴퓨터마다 따로 두는 기록이라 갱신은 프로그램만 바꿉니다. DB를 git으로 나르던 옛 판에서 넘어올 때도 `jocbo.db`는 그대로 남습니다.
- 프로그램 파일 중 이 컴퓨터에서 바뀌었거나 git이 모르는 파일이 있으면, 덮어쓰기 전에 폴더를 `jocbo-backup-날짜-시각`으로 통째로 복사해 둡니다.
- 압축파일로 받았던 폴더도 git이 있으면 그 자리에서 git으로 이어 받습니다. git이 없으면 최신 압축파일로 덮어씁니다.
- 받기에 실패하면 옛 판으로 넘어가지 않고 멈춰서 알립니다.
- 설치 폴더 안의 `install.bat`을 눌러도 됩니다. 실행 중에 자신이 바뀌지 않도록 임시 폴더의 사본으로 넘어가서 돕니다.

손으로 갱신할 때는 PowerShell에서 `.\stop.bat` → `git pull` → `.\start.bat` 순서로 합니다. 서버가 도는 중에는 파일이 잠겨 `git pull`이 깨집니다.

`stop.bat`은 이 폴더의 파이썬으로 뜬 uvicorn과 8000번을 잡고 있는 파이썬을 멈추고, 포트가 실제로 풀렸는지 확인합니다. 돌고 있는 서버가 없으면 그렇게 알립니다.

어느 계정·어느 폴더에서도 그대로 동작합니다. 배치는 자기 파일이 있는 폴더를 기준으로 삼고, 앱도 DB와 첨부 경로를 파일 위치에서 계산합니다.

## 손으로 실행 (Python 3.12 권장)

Windows PowerShell에서 저장소 폴더를 열고:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m uvicorn backend.main:app --reload
```

macOS / Linux:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn backend.main:app --reload
```

http://127.0.0.1:8000 에서 회원가입 후 로그인합니다. **가상 가족 예제 추가**로 본인 계정에 예제를 만들 수 있습니다. API 문서는 `/docs`입니다. 기본 모드는 `jocbo.db` SQLite 파일을 자동 생성하므로 별도 DB 설치 없이 확인할 수 있습니다.

## PostgreSQL 실행

Docker와 Docker Compose가 있다면:

```sh
docker compose up --build
```

http://127.0.0.1:8000 에 접속합니다. PostgreSQL 17과 앱이 함께 시작되고, DB와 첨부파일은 Docker 볼륨에 보관됩니다. 초기 빈 DB에서 `db/schema.sql`이 적용됩니다. 기본 암호는 로컬 샘플 전용이며 공개 서비스에 그대로 사용하지 마세요.

이미 설치한 PostgreSQL을 사용할 경우 빈 DB를 만든 뒤:

```sh
psql -d jocbo -v ON_ERROR_STOP=1 -f db/schema.sql
```

PowerShell에서 연결 설정 후 앱을 실행합니다:

```powershell
$env:DATABASE_URL='postgresql+psycopg://사용자:비밀번호@localhost:5432/jocbo'
.\.venv\Scripts\python -m uvicorn backend.main:app --reload
```

`.env.example`은 설정 참고용입니다. 앱이 `.env`를 자동으로 읽지는 않으므로 환경변수로 지정하세요. SQLite 데이터가 PostgreSQL로 자동 이관되지는 않습니다.

## 샘플 SQL

선택적으로 `psql -d jocbo -v ON_ERROR_STOP=1 -f db/seed.sql`을 실행합니다. SQLite에서는 `.venv`의 Python으로 `python -m db.seed`를 실행합니다. Compose에서는 `docker compose exec app python -m db.seed`를 사용합니다.

- 데모 로그인: `demo@example.test`
- 데모 비밀번호: `DemoFamily123!`
- seed는 가상 인물 4명, 부모-자녀와 배우자 관계를 생성합니다. 반복 실행 시 중복 삽입을 하지 않습니다.
- 공용 데모 계정은 테스트 환경에서만 사용하세요. 기본 시작 시 자동 생성하지 않습니다.

## 화면과 기능

1. 상단의 **+ 새 족보**를 누르면 레이어 창이 열려 족보를 만들고, 왼쪽에서 족보를 고릅니다. **예제 추가**도 상단에 있습니다.
2. 족보를 고르면 제목 아래에 성씨·본관·파명·권이 가로로 펼쳐지고, 왼쪽 **나의 족보** 아래에 그 족보를 고치는 칸이 이어서 나옵니다. 사이드바와 본문 사이의 세로선을 마우스로 끌면 사이드바 폭이 바뀌고(두 번 누르면 기본값), 그 폭은 브라우저에 기억됩니다.
3. 족보 칸은 한글로 먼저 적고 **한자로 바꾸기**를 누르면 글자마다 한자를 골라 채웁니다. 인물의 한자명도 같은 창을 씁니다.
4. 족보명·성씨·본관·파명·시조를 한자로 적어도 입력칸 아래에 한글 음이 함께 보입니다(`淸道金氏大同譜` → 청도김씨대동보). 보기 탭 오른쪽 끝의 **한글로 보기**는 제목·정보줄·인물 목록·가계도·족보책을 한글로 읽습니다. 인물 목록과 가계도는 이름이 한글/한자로 바뀌고 다른 표기가 아래에 따라오며, 족보책은 `아들 장순 1983년 계해 2월 3일생`처럼 칸 모양 그대로 한글이 됩니다. 왼쪽 **나의 족보** 옆의 버튼은 사이드바(족보 목록과 편집 칸)만 따로 바꿉니다. 누르면 족보 목록·제목·정보줄과 왼쪽 입력칸이 모두 한글로 바뀝니다. 한글로 본 채 저장해도 손대지 않은 칸은 원래 한자 그대로 남습니다. 제목 아래 정보줄은 성씨/가문 · 본관 · 파명 · 권 · 페이지(원본 책의 쪽) · 시조 순이며, 비어 있는 칸은 빠집니다.
5. 인물 등록에서 한글명, 한자명, 본관, 세대, 성별, 출생·사망일, 생애 기록을 입력합니다. 본관은 새 인물을 등록할 때 족보의 본관이 기본값으로 들어가며, 혼인으로 들어온 사람은 친가 본관으로 고쳐 입력합니다. 족보책의 배우자 표기(`配天安全氏京愛`)에 쓰입니다.
6. 인물 카드를 누르면 수정·삭제와 파일 업로드를 할 수 있습니다. 삭제 시 관련 관계와 첨부파일도 삭제됩니다.
7. **가족 관계**에서 기준 인물과 관계(부모·배우자·자녀·형제자매)를 고르고 **관계 추가**를 누르면 인물 등록 창이 그 관계로 설정된 채 열립니다. 새 인물을 등록하거나 기존 인물에서 고를 수 있습니다. 인물 창의 **+ 가족 추가**도 같은 창을 엽니다. 본인과의 관계, 족보 간 연결, 중복 관계, 조상 순환을 차단합니다.
8. 한글명·한자명·메모를 검색합니다. **인물 목록**은 결과만 추려 보이고, **가계도**와 **족보책**은 전체를 그린 채 해당 인물 위치로 이동해 금색 테두리로 표시합니다. **전체 보기**를 누르면 검색어·표시·기준 인물이 풀리고 화면도 처음 위치로 돌아갑니다. 기준 인물을 고르면 관계 목록이 그 사람의 직계로 좁혀지고, 비우면 전체가 나옵니다. 목록은 윗세대부터, 한 사람 안에서는 혼인을 먼저 적는 순서입니다.
9. 세대는 관계를 따라 맞춰 보입니다. 자녀는 부모보다 한 세대 아래이고, **배우자는 같은 세대**입니다. 1세대로 들어간 사람을 30세 아버지에 자녀로 이으면 31세가 되고, 그 사람의 배우자도 31세로 따라갑니다. 저장된 값은 그 사람을 고쳐 저장할 때 맞춰집니다. 가계도는 기록된 세대를 그대로 줄로 쓰고, 부부를 한 묶음으로 놓아 자녀 선이 부부 사이에서 내려옵니다. 부모 한 사람만 기록되어 있어도 배우자가 한 명이면 선은 부부 사이에서 나옵니다. 형제자매는 **왼쪽부터 아들(나이 많은 순) → 딸(나이 많은 순)** 으로 놓고, 생일을 모르는 사람은 같은 성별의 뒤에 둡니다. 배우자가 한 명뿐이면, 아버지만 기록된 자녀와 부모 둘 다 기록된 자녀를 같은 부부의 자녀로 한데 모읍니다(재혼이면 혼인별로 나뉩니다).
10. 가계도 카드에 마우스를 올리면 위·아래·좌·우에 **+** 가 나타나 부모·자녀·배우자·형제자매를 그 자리에서 추가합니다. 인물 등록 창이 관계가 지정된 채 열리고 세대·본관이 미리 채워지며, 저장하면 인물과 관계가 함께 생성됩니다. 형제자매는 공통 부모로 잇는 관계이므로 부모 기록이 없으면 점선으로 표시하고 이유를 알립니다.
11. **배우자를 등록하면** 그 사람에게 이미 달린 자녀가 두 분 모두의 자녀로 함께 기록됩니다(배우자가 한 명일 때). 배우자를 두 번째로 등록하면 어느 혼인 소생인지 물어, 기존 자녀를 그 혼인으로 옮기거나 새 자녀를 등록하거나 나중으로 미룰 수 있습니다. 가계도에서는 혼인마다 자녀 선이 따로 내려옵니다.
12. **혼인으로 들어온 사람의 친가 윗대**는 이 족보의 계대가 아니므로 세대 대신 `外家` 로 적고 카드와 이음선을 점선으로 그립니다. 족보책에는 싣지 않고, 배우자 줄의 `부 경진` 처럼 원래 자리에만 남습니다. 배율 줄 오른쪽에 범례가 나옵니다.
13. 가계도 위의 **표시 항목**에서 세대·한자명·본관·출생일·사망일·나이·사진·기록/생애·성별 색을 켜고 끕니다. 사진은 인물에 첨부한 PNG·JPG 중 첫 장을 쓰며, 선택값은 브라우저에 기억됩니다.
14. 가계도와 족보책 미리보기는 **끌어서 움직입니다** — 화면 아래 스크롤 막대를 잡을 필요가 없습니다. 가계도는 빈 곳이나 카드의 여백을 끌면 움직이고, 끌지 않고 그냥 누르면 인물 창이 열립니다. 카드의 이름·설명 글자 위를 끌면 **그 글자가 선택**되어 복사할 수 있고, 이때는 인물 창이 열리지 않습니다. 족보책의 글줄 위에서는 끌어도 움직이지 않고 **그 글자만 선택**되어 복사할 수 있습니다.
15. 보기 탭·한글 전환 줄과 배율 줄은 **화면에 떠 있어**, 긴 가계도나 여러 장짜리 족보책을 내려봐도 그대로 손에 닿습니다.
16. 배율은 위의 `−` `+` `100%` `맞추기` 버튼으로 조절하고, **Ctrl + 마우스 휠**로는 커서가 가리키는 곳을 기준으로 확대·축소합니다. 화면별로 기억되며 인쇄에는 영향을 주지 않습니다.
    - 보기 창 **아래의 가는 막대를 위아래로 끌면** 창 높이가 바뀝니다. 정한 높이는 기억되고, 막대를 두 번 누르면 기본 높이로 돌아갑니다. 막대를 누른 뒤 ↑/↓ 키로도 조절합니다(Shift와 함께 누르면 크게).
    - 배율 줄의 **전체 화면**을 누르면 가계도나 족보책이 브라우저 창 전체를 차지합니다. **Esc**나 **전체 화면 닫기**로 돌아옵니다. 전체 화면에서 인물을 고쳐 저장해도 그대로 유지되고, 인물 창은 그 위에 열립니다. 전체 화면에서는 보기 탭 옆의 전환 버튼이 가려지므로, 배율 줄에 **한글로 보기 / 한자로 보기** 버튼이 함께 나옵니다. 모니터 전체로 보려면 브라우저의 **F11**을 함께 씁니다.
17. 족보책 미리보기는 한 면에 6개 세대 칸을 그리고, 다음 면은 앞 면의 마지막 세대를 다시 첫 칸에 올려 이어붙입니다. 사람마다 칸 너비를 재어 실제 족보처럼 **자녀의 첫 칸을 부모 칸 바로 아래에서 시작**하고, 형제자매를 아들(나이 많은 순) → 딸(나이 많은 순)으로 왼쪽에 잇습니다. 자녀가 더 왼쪽에서 시작해야 하면 부모도 첫 자녀 위로 옮겨 섭니다. 한 면에 다 들어가지 않으면 같은 세대 칸을 되풀이한 다음 면으로 이어지고, 사람 칸이 두 면에 걸쳐 잘리지 않습니다. 쪽 번호는 면마다 하나씩 올라가며(617, 618 …), 화면에서도 각 면 위에 보입니다. 원본 책이 어떤 세대에서 다른 쪽으로 건너뛰면 족보 정보의 **쪽 이어짐**에 `31세 660쪽`처럼 적습니다. 그 세대로 시작하는 면이 그 쪽 번호가 되고, 뒤로는 거기서부터 이어 셉니다(여럿이면 `31세 660쪽, 36세 702쪽`). 그 세대 아래로 아직 아무도 없어도 그 면(예: 660쪽, 31세부터)은 만들어집니다. 기록이 없는 세대도 칸을 비워 그려 가로·세로 선이 면 전체에 이어집니다. 이름은 성씨를 떼고 적고, 날짜는 `一九五四年甲午五月二十九日生`처럼 간지를 붙인 한자로 표기합니다.
18. **족보책 인쇄 / PDF**를 누르고 브라우저의 **PDF로 저장**을 선택합니다. 장마다 위 왼쪽에 원본 책의 쪽 번호(족보 정보의 **페이지**부터 617, 618 …), 위 오른쪽에 인쇄한 날짜·시간, 아래에 장 번호(1 / 3)가 찍힙니다. 브라우저가 붙이던 앱 제목과 주소(127.0.0.1:8000)는 찍히지 않습니다. 검색을 해제하고 선택한 족보 전체를 출력합니다. 전통 서책을 참고한 세대 구분·세로 한자명·생애 기록 형식이며 특정 문중의 편집 규격을 보증하지 않습니다.

## 저장 전 확인과 날짜 규칙

- 인물 저장·삭제, 관계 삭제, 자녀 이동은 **확인 창**을 거칩니다. 무엇이 어디에 기록되는지 적고, 초점은 **취소**에 있어 엔터를 다시 눌러도 저장되지 않습니다.
- 확인 창은 저장될 날짜를 `출생 1956년 4월 27일`처럼 한글로 되읽어 줍니다. 브라우저의 날짜 칸은 월에 43을 치면 4만 받고 일에 32를 치면 31로 깎는 등 입력을 조용히 고치므로, 저장 전에 눈으로 확인할 자리가 필요합니다.
- 없는 날짜(2월 31일, 평년 2월 29일), 잘못된 형식, 오늘 이후의 날짜, 출생일보다 이른 사망일은 화면과 서버 양쪽에서 막고 어느 칸이 왜 잘못인지 알립니다.
- 출생일·사망일 옆의 **지우기**로 연·월·일을 한 번에 비웁니다.

## 한자와 한글

- 전환 스위치는 셋이며 서로 간섭하지 않습니다. **보기 탭 옆**은 인물 목록·가계도·족보책, **나의 족보 옆**은 사이드바, **각 창 안**은 그 창만 바꿉니다. 각각 따로 기억됩니다.
- 성별도 함께 바뀝니다. 한자로 볼 때는 족보가 쓰는 `子`·`女`·`未詳`으로 적고 아래에 한글 음을 답니다. 저장되는 값은 언제나 한글입니다.
- 족보책에서 인물 맨 위의 `子`·`女`(한글로 볼 때 `아들`·`딸`)는 그 계파의 친가족임을 나타내는 표시라, 이름·기록과 섞이지 않도록 굵은 고딕(맑은 고딕 Bold)으로 찍습니다. 혼인으로 들어온 배우자는 따로 줄을 받지 않고 친가족 줄 안에 `配`·`夫`로 적으므로 이 표시가 붙지 않습니다.
- 한자 변환기는 족보 정보의 각 칸, 인물의 한자명, 판독 결과의 각 줄에서 쓸 수 있습니다. 한글로 적은 뒤 칸 옆의 **한자**를 누르면 글자마다 후보를 고릅니다.

## 족보책 글꼴

족보책은 **한컴바탕(HCR Batang)** 을 먼저 쓰고, 없으면 KoPub바탕 → 나눔명조 → 바탕 순으로 찾습니다.

- 윈도우 기본 **바탕(Batang)은 마지막 대안**입니다. 작은 크기에서 점으로 찍은 비트맵 글자를 쓰는데, 세로쓰기에서 위치가 어긋나 `二`가 `九`에 붙고 `二二`가 겹쳐 보입니다. 또 `〇` 글자가 없어 다른 글꼴에서 빌려 오므로 `九〇`의 간격이 틀어집니다.
- 한컴바탕은 한컴오피스를 설치하면 들어옵니다. 한컴바탕·KoPub바탕·나눔명조가 모두 없는 컴퓨터에서는 바탕으로 찍혀 위 문제가 다시 보일 수 있습니다.
- `一`은 가로획 하나뿐이라 칸 위아래가 크게 비어 세로줄에서 앞뒤 간격이 벌어집니다. 날짜·기록·배우자 줄의 `一`만 위아래 빈 곳을 줄여 다른 글자 사이와 비슷하게 맞춥니다. 다른 글자의 간격은 바꾸지 않습니다.
- 이름은 진짜 굵은 글꼴(한컴바탕 Bold)로 찍습니다. 굵은 글꼴이 없는 글꼴을 억지로 굵게 하면 브라우저가 획을 옆으로 한 번 더 찍어 번져 보이므로, 굵게 흉내 내기는 꺼 두었습니다.

## 알림과 창

- 알림은 화면 **정중앙 위쪽의 네모 상자**에 뜹니다. 화면 위쪽에 가로로 길게 붙어 있을 때는 가계도를 확대해 보는 중에는 보이지 않았습니다. 확인 알림은 4.5초, 오류는 14초 뒤 사라지고 누르면 바로 닫힙니다.
- 인물 창이 화면보다 길면 **저장 · 취소 · 삭제** 줄이 창 아래에 붙어 따라다닙니다. **+ 가족 추가**는 성격이 다른 동작이라 줄 맨 오른쪽에 떨어져 있습니다.
- 첨부한 PNG·JPG는 그림으로 내려보내므로 인물 사진이 카드와 인물 창에 그대로 보입니다. PDF는 내려받기로 남습니다.
- 화면 문구는 개조식으로 적습니다 — `전체 36명 중 1명`, `김종환 — 저장 완료`.

## 족보 이미지 판독

**+ 인물 등록** 옆의 **족보 이미지 올리기**에서 족보 사진(PNG·JPG, 최대 20MB)을 올리면 족보에 보관되고, 왼쪽에 크게 띄운 채 오른쪽에서 인물을 옮겨 적습니다. 확대·축소와 끌어서 이동을 지원합니다.

**판독**을 누르면 사진을 읽어 각 줄을 채웁니다.

- 판독은 이 컴퓨터에서만 이루어집니다. API 키도 비용도 없고 사진이 밖으로 나가지 않습니다.
- 지면 문법을 씁니다. 세로 열을 오른쪽에서 왼쪽으로 읽고, 가로 단마다 한 세대로 봅니다. `子`·`女`는 친자, `配`는 혼인으로 들어온 사람이며 본관과 성씨를 함께 가져옵니다. `庚子`의 子나 주석 안의 子는 사람으로 세지 않습니다.
- **판독 모델은 PP-OCRv6**입니다. 번체와 간체를 함께 배운 모델이라 족보의 글자를 인쇄된 그대로 읽습니다(`魯佶`, `魯錫`, `勝世`, 배우자 아버지 `泰鎬`·`相範`). 예전 모델(간체 전용)은 이 글자들을 비슷한 모양의 다른 글자로 읽었습니다(`結上`, `魯`, `滕世`, `甘泰`·`斗相`). 모델은 처음 판독할 때 한 번 내려받습니다. 옛 판독기를 쓰던 설치는 `start.bat`이 묻지 않고 새 판독기로 바꿉니다. 간체로 나온 글자는 번체로 되돌리되, 한국 이름에서 뜻이 달라지는 글자는 예외로 둡니다(`朴`은 `樸`이 아닙니다).
- 같은 열이 사진 기울기로 조금 겹쳐 읽혀도 한 열로 이어 읽고, 단의 머리가 아니라 열 중간에서 시작하는 `子`·`女`(남편 기록에 딸린 자녀 목록)는 새 사람으로 세지 않습니다.
- 날짜의 간지를 검산으로 씁니다. 연도와 간지가 어긋나면 그 줄을 붉게 표시합니다.
- 휴대폰 사진의 회전 정보(EXIF)를 따라 세운 뒤 읽습니다. 가로 괘선을 찾아 단을 나누고, 사진이 조금 기울어도 괘선의 기울기를 따라 나눕니다.
- **펼친 두 쪽을 한 장에 찍어도 됩니다.** 두 쪽은 종이가 휘어 괘선 높이가 서로 달라서, 괘선이 건너지 않는 가운데 골을 찾아 쪽을 나누고 쪽마다 괘선을 따로 찾습니다. 두 쪽이 만나는 곳에서 같은 단의 괘선끼리 짝지어, 왼쪽 쪽의 단을 오른쪽 쪽의 같은 세대로 이어 읽습니다. 오른쪽 쪽에서 시작해 왼쪽 쪽으로 넘어간 기록도 한 사람으로 읽습니다. 휘어져 가늘고 기울어진 괘선도 찾습니다.
- **펼친 두 쪽에 다른 가족이 새로 시작하면 나눕니다.** 오른쪽 쪽에서 이어 온 가족의 가장 윗세대보다 더 윗세대인 사람이 왼쪽 쪽에 있으면, 그 사람부터는 이어 온 가족의 후손일 수 없으므로 새 계통으로 봅니다. 그 가족의 가장 오른쪽 열이 경계이고, 경계 왼쪽은 세대와 상관없이 새 가족, 오른쪽(가운데 골을 넘어 이어진 기록 포함)은 이어 온 가족입니다. 화면에는 **여기부터 다른 가족** 구분선이 생기고, 그 아래 줄은 **새 족보(계통)로 따로 만들기**(기본) · 이 족보에 함께 · 등록하지 않음 · 다른 족보 중에서 골라 등록합니다. 새 족보는 이 족보의 성씨·본관·파명·권·페이지·시조를 그대로 받고, 이름 끝에 새 가족의 가장 윗사람을 붙입니다(예: `(鎭元 계통)`). 다른 가족의 줄은 이 족보의 동명이인과 짝짓지 않습니다.
- 여백의 세대 표기를 못 읽은 사진이라도, 윗대 계통 표시가 있으면 그 마지막 이름(아버지)을 족보에서 찾아 세대를 정합니다: `芝淑 相錫 正煥` 위의 `澈純`은 金正煥(30세)의 아들이므로 그 단이 31세, 다음 단이 32세입니다.
- **세대는 사진에서 읽습니다.** 여백의 `二十六世` 표기를 찾으면 각 줄의 세대를 그대로 채웁니다. 일부 표기가 깨져 읽혀도(`三十世` → `十川`) 나머지 표기와 단 순서로 채우고, 표기를 못 읽으면 윗대 계통 표시의 아버지를 족보에서 찾아 정합니다. 둘 다 없으면 첫 단을 1세대로 두므로 각 줄의 **세대** 칸에서 고칩니다.
- 사람은 **열의 머리에서만** 시작합니다. `東國(동국)女`처럼 배우자의 아버지를 적은 `女`, 딸의 기록에서 남편 뒤에 나오는 자녀 `子`·`女`, 혼자 떨어진 `子` 한 글자는 사람으로 세지 않습니다. `一九`처럼 숫자로만 된 이름도 버립니다. `英子`처럼 `子`로 끝나는 이름은 이름으로 읽습니다.
- 옛 족보가 딸을 사위 이름으로 적은 `女 嚴柱華 寧越人`은 이름 없는 딸(`金氏`)로 올리고, 기록에 `사위 嚴柱華(寧越人) · 딸 이름 미기재`를 남깁니다.
- **휘어진 괘선도 따라갑니다.** 비스듬히 찍어 괘선이 활처럼 휘거나 가늘고 흐려도, 짧게 끊긴 조각을 거의 이어지는 것끼리만 이어 한 줄의 곡선으로 찾습니다(글자 줄은 열 사이 빈칸에서 끊기므로 이어지지 않습니다). 괘선에 붙은 글자도 괘선으로 셉니다. 한쪽 쪽이 조금만 찍혀도 가운데 골을 찾고, 괘선이 보이지 않는 조각은 옆 쪽의 괘선으로 읽습니다. 사진 가장자리에 잘린 열은 읽지 않습니다.
- **윗대 계통으로 시작하는 기록도 읽습니다.** 여러 쪽을 건너 한 집안이 다시 이어지는 곳에서 책은 아들 이름 위에 윗대 이름을 작게 적고(`芝淑 相錫 正煥` 위의 `澈純`) `子`를 붙이지 않습니다. 짝수 개의 한자 이름만으로 된 작은 칸을 이 계통 표시로 읽어 새 사람을 시작합니다(계통 표시는 기록에 넣지 않습니다). 날짜·표시 글자나 지명·주석 글자(山·洞·公·后·堂 …)가 든 칸, 바로 앞 칸에서 열린 괄호의 계속(배우자 이름의 한글 음이 한자로 뭉개진 것)은 계통으로 보지 않습니다. 이름을 놓치면 `初名`처럼 주석 글자를 이름으로 삼지 않고 이름 칸을 비웁니다.
- 괄호에 닿은 글자가 많아 두꺼워 보이는 괘선도 괘선으로 찾습니다(x마다 가운데 높이를 따라감).
- **딸의 기록은 딸의 것만 적습니다.** `夫`부터는 남편 줄로 갑니다: 남편의 이름·본관은 그 칸에, 기록에는 남은 것만(`父 學龍(학룡) · 子 東炫(동현) · 女 志娟(지연)`) 적고, 누구의 남편인지는 배우자 연결이 말해 주므로 다시 적지 않습니다. 딸의 기록에는 학력·수상처럼 딸 자신의 것만 남습니다(`연세대학교 대학원 졸업 교육공학 석사 · 2014.8.31 대통령표창`). 사위 이름으로만 적힌 딸(`女 嚴柱華 寧越人`)은 `딸 이름 미기재`로, 사위는 본관을 갖춘 따로 한 줄로 올립니다.
- **배우자를 함께 연결합니다.** `配`는 바로 앞 아들(이름을 놓친 아들 포함)의 아내, 딸 기록의 `夫`는 그 딸의 남편입니다. 딸의 남편(`夫 金熙旋 瑞興人 父學龍`)은 본손이 아니어도 배우자로 잇기 위해 따로 한 줄(남 · 본관 瑞興 · 기록 `女 金順熙의 夫 · 父 學龍`)로 올립니다. **모두 등록** 때 두 사람이 같은 족보에 들어가면 배우자 관계를 만듭니다. 부모·자녀 관계는 전처럼 등록 후 지정합니다.
- 이름 칸(`子`·`女`)에서 이름이 한 글자만 읽히면(`子魯` ← `子魯錫`) 그 칸만 잘라 두 배로 키워 다시 읽습니다. 처음 읽은 글자를 그대로 첫 글자로 가진 두 글자 이름이 나올 때만 바꿉니다.
- 한 단의 아들들이 이름 첫 글자(돌림자, `魯錫`·`魯世`의 `魯`)를 함께 쓰는데 그 글자가 없는 이름(`結上`)은 잘못 읽힌 것으로 보고, 이름만 잘라 여러 크기로 다시 읽어 돌림자로 시작하는 결과를 씁니다(`魯佶`).
- 한 기록에 출생일이 두 번 나오면 두 번째는 이름을 놓친 다음 사람의 것이므로(`子亨純` 누락) 이름 칸이 빈 줄로 따로 올립니다.
- 판독기가 이름 머리를 놓쳐 날짜만 남은 기록은 버리지 않고 **이름 칸이 빈 줄**로 올립니다(`이름 판독 안 됨 · 初名 泰東`). 이름을 채워야 등록됩니다.
- 배우자의 `父`는 이름 바로 뒤에서 괄호 한글이 닫히고 `女`가 오는 곳에서 읽습니다(`世東(세동)女` → `父 世東`). 앞의 괄호 한글이 엉뚱한 한자로 읽혀 붙어도 끝은 거기서 정해집니다. 판독이 아버지 이름 한 글자를 놓치면 틀릴 수 있으므로(`相範` → `斗相`), 족보에 이미 `父`가 적힌 사람에게는 판독의 `父`를 덧붙이지 않습니다. `字`·`初名`·`夫`도 같습니다. 본관 한 글자를 놓친 배우자(`金寧金氏` → `金金氏`)도 본관만 비운 채 올립니다.
- 이름에서 자주 틀리는 글자는 바로잡습니다: `鐘`→`鍾`, `鎖`→`鎭`, `磨`→`磬`, `填`→`埴`, `鬥`→`斗`, `曹`→`曺`, 본관 `寕`→`寧`, `尚`→`尙`.
- 출생일과 사망일을 함께 읽습니다. `正月`은 1월, `三月五卒`처럼 `日`이 빠진 날짜도 읽습니다. 판독기가 `己亥`를 `已亥`로, `戊申`을 `戊中`으로 읽는 혼동은 간지 자리에서 바로잡습니다.
- 기록 칸에 `字`·`初名`·`號`, `墓 … 坐`, 딸의 `夫`와 외손 `子`, 배우자의 `父`, 연도 없는 `忌 九月十九日`(기일 9월 19일)을 옮깁니다. 딸의 아들은 본손으로 세지 않습니다.
- **한글은 읽지 못합니다.** 판독 모델이 한자 전용이라 이름 옆 한글 음, 괄호 안 한글, 한글로 적힌 생애(학력·경력)는 엉뚱한 한자로 읽히므로 버립니다. 이 부분은 손으로 채웁니다.
- **판독 결과는 제안입니다.** 원본과 대조해 고친 뒤 **모두 등록**을 눌러야 기록됩니다. 목판 인쇄는 획이 뭉개지거나 비슷한 글자로 읽히는 일이 잦습니다(`鍾`↔`鐘`, `磬`↔`磐`). 읽히지 않은 사람은 같은 화면에서 손으로 채웁니다. 쪽 위·아래·옆에 인쇄된 페이지 번호(612)가 읽히면 `판독 N명` 옆 **페이지** 칸에 채워지고, 읽히지 않으면 비워 두며 손으로 고칠 수 있습니다.
- 한 쪽은 통째로 들어가거나 아무도 들어가지 않습니다. 한 줄이라도 잘못되면 전체가 등록되지 않습니다.
- 이미 있는 이름과 겹치면 그 줄에 **업데이트**(연한 파랑)가 표시되고, 등록하면 그 사람의 기록을 채웁니다. 비어 있거나 `미상`인 칸만 채우며 이미 적힌 값과 세대는 건드리지 않습니다. **기록**은 이미 적힌 내용을 그대로 두고, 판독에서 새로 나온 항목 중 아직 없는 것만 아래에 덧붙입니다(괄호 속 한글 음은 비교에서 뺍니다). 판독 줄의 기록 칸은 업데이트했을 때 남을 모습 그대로 보여 줍니다: 족보에 이미 있는 기록이 먼저, 판독에서 새로 나온 항목은 그 아래 줄에 붙어, 한 칸에서 비교할 수 있습니다. 족보에 없는 이름의 줄에는 **신규 등록**(진한 초록)이 표시됩니다. 같은 사람을 다시 읽은 것이므로 따로 한 명 더 만드는 선택지는 두지 않습니다. 다만 한글명은 같고 한자가 다르면(김철순 `金哲純` ↔ `金澈純`) **동명이인**으로 보고 **업데이트**와 **별도 등록**을 함께 보여 줍니다. 이 줄은 기존 기록을 덧붙여 보여 주지 않으며, **모두 등록**에서는 별도 인물로 등록합니다. 줄의 **업데이트**·**신규 등록** 버튼을 누르면 그 줄만 바로 반영하고(채운 칸을 알림으로 알려 줍니다), 줄 왼쪽에 초록 표시가 붙습니다. 다른 가족으로 나뉜 줄은 **모두 등록**에서 정한 곳으로 등록합니다.
- 기록 칸에는 예시 문구를 두지 않습니다. 흐린 예시(`父 東國`)가 모든 줄에 누군가의 아버지 이름이 들어간 것처럼 보였습니다.

### Claude로 판독

**Claude로 판독**은 사진을 Anthropic의 Claude(`claude-opus-5`)에게 보내 읽힙니다. 이 컴퓨터의 판독기가 못 읽는 **한글**(이름 옆 음, 괄호 속 한글, 학력·경력 같은 생애)과 작은 주석(字·初名·忌·墓), 배우자의 아버지까지 읽어 같은 줄들을 채웁니다.

- 처음 한 번 **Claude API 키**가 필요합니다. <https://console.anthropic.com>에서 발급해 판독 창의 칸에 넣고 **키 저장**을 누르면, Anthropic에 맞는 키인지 확인한 뒤 이 컴퓨터의 `.env`에만 저장합니다(git에 올라가지 않습니다).
- **사진이 Anthropic으로 전송됩니다.** 버튼을 누를 때만 보냅니다.
- 사용료가 듭니다. 펼친 두 쪽 사진 한 장에 대략 300~700원입니다. 한 번 읽는 데 1~3분 걸립니다.
- 펼친 두 쪽은 가운데 골에서 쪽을 잘라 오른쪽 쪽부터 따로 보내, 쪽마다 최대 해상도(긴 변 2576px)로 읽힙니다.
- 결과는 이 컴퓨터의 판독과 같은 모양입니다: 세대, 한글명(인쇄된 한글 음 그대로), 본관, 생몰일, 기록, 배우자 연결, 다른 가족 구분. 읽을 수 없는 글자는 `□`로 남깁니다. **결과는 제안이므로 원본과 대조한 뒤 등록합니다.**

기록 칸의 한자 낱말에는 한글 음을 괄호로 붙입니다(`父 學龍(학룡)`, `사위 嚴柱華(엄주화) 寧越人(영월인)`). 이 컴퓨터의 판독은 한글을 못 읽으므로 앱의 한자 음 표로 붙이고, 페이지가 이미 괄호 한글을 준 낱말과 `初名` 같은 머리말은 그대로 둡니다.

판독기는 선택 설치입니다. 설치하지 않아도 앱은 그대로 동작하고 **판독** 버튼이 설치 방법을 알립니다.

```powershell
.\.venv\Scripts\python -m pip install -r requirements-ocr.txt
```

- 같은 이름이 있으면 덮어쓰므로 여러 번 실행해도 중복이 생기지 않습니다.
- 기록을 더 넣어도 다른 컴퓨터에는 자동으로 반영되지 않습니다. 각 컴퓨터의 DB는 따로입니다.

## 파일 저장과 인증

첨부파일 본문은 `uploads/` 또는 `UPLOAD_DIR` 환경변수 경로에 저장하고 DB에는 원래 이름·저장 키·소유 인물을 기록합니다. PNG/JPG/PDF만 최대 5MB로 제한하고 파일 시그니처를 확인합니다. 다운로드는 로그인 및 족보 소유자 확인 후에만 가능합니다. 업로드 폴더를 공개 정적 경로로 노출하지 않습니다. DB와 첨부파일 디렉터리를 함께 백업해야 합니다.

비밀번호는 사용자별 salt와 scrypt로 해시하며, 세션은 임의 토큰의 해시와 만료 시각을 DB에 저장합니다. 쿠키는 HttpOnly, SameSite=Strict이고 24시간 만료입니다. HTTPS 배포 시 `COOKIE_SECURE=1`을 설정하세요.

초기 MVP에는 이메일 인증·비밀번호 재설정·로그인 시도 제한·다중 사용자 공동편집·백신 검사·음력 날짜·대규모 가계도 자동 배치가 없습니다. 인터넷 공개 운영 전에는 인증 강화, HTTPS, 요청 크기/속도 제한, 백업, 파일 검사 등을 구성해야 합니다. 본인 소유의 족보만 접근할 수 있습니다.
